# What comes next

Mneme 1.0 focuses on one complete learning loop: Source Note → reviewed Concept → reviewed Cards → FSRS review. The [first release](../CHANGELOG.md) includes manual authoring, Markdown ownership, and explicit AI approval.

The next priorities are:

- **Make the first session easier:** clearer onboarding, realistic example notes, and better explanations of proposal approval and scheduling.
- **Learn from real workflows:** fix reproducible bugs and improve the interactions people use to capture, edit, and review.
- **Expand compatibility evidence:** verify Windows and mobile behavior before claiming the same support as the accepted macOS build.
- **Prepare community distribution:** work toward Obsidian's community-plugin review requirements.
- **Improve contributor access:** keep the developer setup, CI, issue reports, and architecture notes useful to new contributors.

These are directions, not a dated delivery commitment. Suggest a concrete learning problem through [a feature request](https://github.com/HetongLin/mneme/issues/new/choose). Small improvements to the core workflow are especially welcome.

Product changes should preserve the existing [architecture decisions](adr/): learner approval for AI knowledge changes, Markdown as the content source of truth, and local, deterministic review.
